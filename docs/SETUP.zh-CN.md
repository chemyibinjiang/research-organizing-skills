# 使用说明

这里有八项可复用技能，覆盖微信和邮件、学术组织、接待、分工、材料交付及突发变更。
各项包含操作说明，必要时配有脚本、空白表或虚构示例；重要决定和发送仍由人确认。

## 仓库里有什么

- `skills/wechat-local-reader`：限定会话和时间读取，区分原话、引用和转发，追溯附件。
- `skills/email-correspondence`：查收件和已发送、记录进展、准备附件邮件、批准后发送并核验。
- `skills/conference-state-handoff`：当前状态、任务归属、变更和跨专题交接。
- `skills/speaker-reviewer-planning`：邀请报告人检索、专业匹配、评委分组、覆盖与回避检查。
- `skills/conference-programme-check`：报告、主持、采访、接送和参观的时间冲突检查。
- `skills/participant-logistics`：嘉宾对接、住宿、餐券、车辆、志愿者任务和服务记录。
- `skills/conference-materials-release`：主持稿、流程单、座次、PPT及打印包的一致性与交付。
- `skills/conference-exception-handling`：核实意外变化、评估影响、提出备选、确认授权、通知和核验解决情况。
- `templates`：项目当前状态、专题交接、联系人和邮件记录的空白模板。
- `tests` 和技能内的测试：仅合成数据，不会连接真实邮箱或读取微信。

具体提问方式和配合流程见[办会使用示例](CONFERENCE_WORKFLOWS.zh-CN.md)。
后六项是会后提炼的通用流程，其中议程和评委分配附有新写的检查器，
不能据此宣称这些打包版本已经在整场会议中运行验证。
异常处理技能配有事件记录模板和七个虚构场景；它辅助决策和交接，不是自动应急系统。

## 怎么开始

1. 先看 [英文安装说明](SETUP.md)，配置 Python 3.11 和依赖。
2. 执行 `python scripts/run_tests.py` 跑离线测试。
3. 执行 `python scripts/install_skills.py` 预览；确认后加 `--apply` 安装。
4. 在仓库外配置自己的账号、文件路径和私有输出目录。已有配置不能整份覆盖。
5. 从一项小的只读任务开始，例如“看这个项目群昨天以来有哪些变动和待办”。

已有不同版本的技能不会被安装器覆盖。微信需要本人授权的数据和已有受保护密钥；
本仓库不提供获取或恢复密钥的功能。没有条件时，使用获得授权的界面或导出方式。
邮箱接入方式须符合服务商和所在单位的授权要求；拥有密码或能够登录不等于已获授权。
示例使用通用的 `work` 配置名及无效示例域名，不对应任何实际单位；不能借用他人的凭据。

## 使用时务必区分

- 已起草、已批准、已发出、已核已发送副本、对方已回复、事情已完成，是不同状态。
- 旧消息的引用不是新的决定；表格生成不等于已经发给会务，更不等于现场落实。
- 发信前核收件人、抄送、正文、附件及最新回信。发送结果不明确时不要直接重试。
- 个人信息、行程、评审材料、聊天、邮箱、密钥都不能上传到这个仓库。
- 本地脚本处理不等于整个AI过程均在本地；使用外部模型处理信息要符合单位要求。

仓库当前公开可见，但尚未选择开源许可证；公开可见不代表已授予复用或再分发许可。
这是个人整理的通用工作流，不代表机构授权或背书；会议原始记录和论文草稿未放入仓库。
