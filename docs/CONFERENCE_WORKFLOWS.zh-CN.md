# 办会技能怎么用

微信读取和邮件处理是操作基础，其余六项把这些操作组织成能交接的工作。
技能内的表格是空白模板，JSON示例全部虚构。实际材料放在仓库之外的私有工作目录。

## 八项入口

| 事情 | 使用技能 | 可以这样问 |
| --- | --- | --- |
| 群里又改了什么 | `wechat-local-reader` | 只读指定群最近两天的消息，列出决定、待办和相关附件，注明来源 |
| 邮件回没回、还差谁 | `email-correspondence` | 核对收件和已发送，整理逐人状态，先拟回复，不发送 |
| 我今天该做什么、交给谁 | `conference-state-handoff` | 对照当前状态和新消息，只列我负责的待办，给负责人和下一步 |
| 请谁报告、谁来评审 | `speaker-reviewer-planning` | 根据主题找专家，说明专业依据；分配评委时检查覆盖、工作量和已申报回避 |
| 这个时间会不会撞 | `conference-programme-check` | 把主持、报告、采访、交通和步行都算进去，未知时间单列 |
| 接待和志愿者漏了什么 | `participant-logistics` | 去重核对接送、住宿、餐券、分组和负责人，不把空白当作已落实 |
| 发给会务的最终材料 | `conference-materials-release` | 保留手改稿，核对名单和流程，做只含最终PDF及打印清单的包 |
| 计划突然变了怎么办 | `conference-exception-handling` | 核实变化和影响，列出备选及决策人，先别通知，明确怎样才算解决 |

## 示例一：主持人临时换人

1. 读取原消息，确认替换的是哪个时段，是否只换主持、不改两人的报告时间。
2. 更新专题记录，写明旧值、新值、来源、批准人和受影响材料。
3. 检查新主持人的报告、交通及其他任务有没有冲突。
4. 准备给议程负责人、新旧主持及相关秘书的消息。经授权发送后逐项记录；
   不能因为Excel改了，就写成“已通知”。

## 示例二：海报晚到、退出或只展示不评奖

1. 稳定编号不自动重排，原摘要ID与展示编号分开，确认具体姓名和资格。
2. 根据主题匹配评委，明确每组规则、回避、工作量及返回结果的时间。
3. 运行分配检查器，检查遗漏、重复、退出者混入和跨组获奖。
4. 若材料已印，做变更页并通知相关评委；不要无谓重做整个大包。
5. 获奖通知、领取确认、财务信息及付款各自记录，不混成一个“完成”。

## 示例三：两组交换实验室

分别建模整批介绍、两组上楼、房间讲解、换场、下楼和校园参观。
采用实际走过的路程时间；共用楼梯、讲解老师和房间按资源检查。
车上带队与校园待命分开，容量包括随车人员。延误后的路线替换先作为候选方案，
由现场负责人确认；检查器不会替你断言人流安全或道路畅通。

## 示例四：交付主持稿和打印包

找到老师最后手改的文件，逐项核对姓名、奖项顺序、颁奖人及合影对象。
需要更新的只是某一页时，也保留原稿并说明新版本。最终交给打印方的包只放
需要打印的PDF和份数清单；PPT交给播放人员，另行记录测试情况。

## 示例五：原计划突然不适用了

从已确认的安排和新证据出发，先判断是事实变化、尚未确认的消息，还是通信结果不明。
列清受影响的人、资源和材料，保留不受影响的部分；提出可行备选、前提和决策截止时间。
由有权限的人确认后，只执行获准的变更并定向通知，再核对关键交接和实际结果。
不能把“有人接手”“发出了邮件”“生成了新版文件”直接当作问题已经解决。

新技能包含[事件记录模板](../skills/conference-exception-handling/assets/incident-record.template.md)，
以及[七个虚构场景](../skills/conference-exception-handling/references/scenarios.md)：
临时换主持、印后退出、邮件超时、两批同时到达、稿件冲突、设备故障和疑似敏感附件。
未知问题不硬套旧案例；先找最影响下一步的缺失事实和决策人。真实事件只记在私有目录。

## 试跑与安装

完整测试：`python scripts/run_tests.py`。
安装预览：`python scripts/install_skills.py`，确认目标目录后加 `--apply`。
安装器会发现八项技能并复制模板、示例、说明和脚本；不会覆盖已有不同文件。
议程和分配检查器只用Python标准库，可以独立运行；不需要微信密钥或邮箱配置。
两个示例的运行命令和退出码见[验证说明](VALIDATION.md)。
