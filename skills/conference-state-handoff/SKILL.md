# Conference State and Handoff

Start with the project's current-state index and relevant topic note. If neither
exists, use [the topic template](assets/topic-handoff.template.md) in a private
working directory. Do not turn the source-code repository into the event database.

## Reconcile Evidence

1. Bound the requested topic and evidence cutoff. Read selected conversations with
   the available WeChat/email workflow, or inspect user-provided exports. State
   coverage gaps, including unread attachments, voice messages and stale exports.
2. Extract who said what, when, and about which specific task. Preserve a source
   reference. A quoted old arrangement is not a new decision. A generic "yes"
   only confirms the request it actually answers.
3. Apply the latest explicit organizer decision to the affected fields. Programme
   authority, contact authority and finance authority may be different people.
   A newer file timestamp alone does not override a human-edited approved copy.
4. Record conflicting evidence with its owners and next clarification; do not
   convert a plausible inference into a confirmed arrangement. Keep original
   evidence and mark superseded instructions instead of deleting them.

## Maintain Usable State

For each action, record an ID, owner, backup where needed, deadline with timezone,
dependency, source, last checked time and next step. Use separate fields for:

- Decision: proposed / confirmed / superseded.
- Communication: not sent / sent / sent-copy verified / acknowledged.
- Execution: not started / in progress / done / blocked.
- Materials: not received / received / validated / delivered / tested, as applicable.

These are independent facts, not one progress bar. An invitation accepted does
not mean slides received; a file produced does not mean printed; a message sent
does not prove that the driver, chair or volunteer accepted the assignment.
An empty field means unknown, not "no" or "done".

## Handoff and Follow-up

Return the few actions requiring attention, ordered by deadlines and dependencies,
with a named owner and evidence. Distinguish the user's actions from matters owned
by the organizing office; do not absorb every unread message into their workload.

When multiple topic chats are in use, give each an agreed scope, current decisions,
exact artifact versions and unresolved questions. One designated maintainer merges
master changes; other chats prepare patches in their own topic directories. Do
not create or message chats merely because this skill is active.

After an authorized change, update the topic note and index together. Preserve
manual edits. A TODO is not a scheduled reminder; only report a reminder as created
after the scheduling tool confirms it. Neither a handoff nor status synchronization
authorizes an external message or shared-table edit.

## Check Before Closing

Can the next organizer identify the current version, responsible person, unresolved
decision and next action without reading the whole conversation? Report what was
actually updated and what remains unverified.
